# Apple — CO-SHOW 대시보드 디자인 참고

사용자 추가 요청: **“Design.md → Apple, 참고해줘.”**

사용자가 제공한 Apple 웹 디자인 분석을 M3–M5 화면 구현의 시각 참고로
사용한다. [제공된 참고 원문](design/apple-reference.md)을 함께 보관한다.
이 문서는 원문의 원칙을 CO-SHOW 운영 화면에 적용하는 기준이다.
기존 설계 스펙 §6.1–§6.4와 운영·안전 계약을 대체하지 않는다.

## 적용할 방향

**실제로 움직이는 드론·차량과 필드가 화면의 주인공이다.** Apple 참고의
제품 중심 표현을 이 대시보드에서는 실시간 3D 장면과 카메라에 적용한다.
제목·패널·조작부는 움직임과 미션 진행을 이해하는 데 필요한 만큼만
강조한다. 화면의 완성도는 장식 수보다 비례·정렬·여백·읽기 쉬운 값에서
만든다.

| Apple 참고의 원칙 | CO-SHOW에 적용 |
|---|---|
| 제품 중심의 큰 시각 영역 | 3D 필드를 가장 크게 두고 로봇·마커·레인·발견 위치를 분명하게 표현 |
| 자신감 있는 제목과 조용한 보조 문구 | 내러티브 → 상태 값 → 보조 라벨의 세 위계 유지 |
| 넉넉하고 일정한 여백 | 8px 중심 간격 체계로 패널 내부와 패널 사이의 간격을 정돈 |
| 표면과 얇은 경계로 구분하는 UI | 글래스 알파·blur·상단 하이라이트를 절제하고 카드마다 그림자를 반복하지 않음 |
| 일관된 버튼 모양과 상호작용 | 일반 명령의 형태·눌림·키보드 포커스를 통일하고 안전 명령은 계약대로 구분 |
| 콘텐츠 비율과 세밀한 마감 | 카메라 원본 비율, 숫자 정렬, 패널 제목 기준선, 고정 높이 내러티브를 일관되게 유지 |

## 확정된 디자인과 함께 적용할 기준

- **색상:** ambient `#0E1530`, cool `#5EE7FF`, warm `#FFB35C`,
  ink `#F4F6FB`, 기존 glass 토큰을 사용한다. Apple 원문의 흰색·검정
  타일 교대나 별도 브랜드 팔레트로 바꾸지 않는다.
- **단계 신호:** blue `#4DA3FF`, red `#FF5A5F`, green `#3DDC97`와
  off의 의미를 보존한다. 미션 상태는 일반 인터랙션의 강조색과 구분해서
  읽히게 한다. 주의색은 기존 계약대로 관리자 화면에 사용한다.
- **서체:** 저장소에 동봉하는 Pretendard 한 가족이다. SF Pro·Inter로
  교체하거나 외부 폰트를 요청하지 않는다. FHD 기준 내러티브 56px/700,
  값 30px/500, 라벨 15px/400과 `tabular-nums`, `clamp()`를 유지한다.
  Apple 참고의 타이포그래피 위계를 적용하되 한글 자간을 과도하게 좁혀
  멀리서 읽기 어렵게 만들지 않는다.
- **레이아웃:** 16:9 한 화면 안에 3D 약 60%, 카메라 4개, 로봇 상태
  6패널, 미션 정보가 함께 보인다. 4개·6개는 리허설 기본값이며 v2.3
  §5.7에 따라 실제 수는 hello의 역할 목록에서 파생한다. 스페어 카메라는
  만들지 않는다. 내러티브는 2줄 고정 높이이며 좌측
  정렬을 따른다. 제품 소개용 세로 스크롤 페이지나 1440px 고정 폭으로
  전환하지 않는다.
- **깊이와 모션:** 필드 조명과 기존 글래스 방향을 유지한다. 추가
  장식용 그라데이션·그림자·지속 애니메이션은 만들지 않는다. 로봇 이동,
  발견 링, 단계 전환과 스펙이 지정한 대기 화면의 느린 공전이 움직임을
  만든다. `fx=low`의 blur·픽셀비 폴백을 보존한다.
- **운영 조작:** 비상착륙은 우상단의 빨간 버튼으로 확인 없이 즉시
  실행하며, 데모 시작의 0.6초 길게 누르기·착륙 중 잠금·연결 끊김 배너를
  유지한다. Apple의 작은 CTA나 단일 파란색 원칙으로 안전 구분을
  없애지 않는다. 비상 버튼을 누를 때 축소 효과로 위치나 누름 판정을
  흔들지 않는다.
- **오프라인:** three.js·폰트·이미지는 모두 로컬 파일이다. 참고 원문의
  CDN·Google Fonts·외부 이미지 제공 방식은 사용하지 않는다.

## 화면별 구현 메모

### 참관자 화면

실시간 필드를 큰 제품 장면처럼 다룬다. 필드 주변의 공간을 확보하고
유리 패널이 드론·차량의 이동이나 발견 위치를 가리지 않게 한다. 카메라
타일은 일정한 크기와 비율로 정렬하고, 필요한 검출·수신 상태만
강조한다. 하단 역할 패널은 표시 이름, 핵심 값, 짧은 상태 문구의 순서로
읽히게 한다. 장식적인 영문 라벨·대문자 트래킹·아이콘은 추가하지 않는다.

### 관리자 화면

읽기 쉬운 운영 정보가 우선이다. 제어 바와 상태 배지는 차분하게
정렬하고, 체크리스트·로봇 표·preflight 진행·이벤트 로그는 기존
와이어프레임대로 유지한다. 여백을 확보하면서 실패 항목·고도·무장 상태를
동시에 확인할 수 있어야 한다. 경고와 장애를 미관 때문에 감추지 않는다.
M6의 관리자 표에는 전체 플릿을 보이고 역할 행과 스페어 행을 구분한다.
로스터 변경·스택 재기동은 v2.3 계약대로 IDLE에서만 허용한다.

## 시각 검증

- M3: FHD·4K에서 3D 영역, 카메라 4개, 상태 6패널, 내러티브가 모두
  보이고 잘리지 않는지 확인한다. 대수 변경에도 코드 수정 없이 배치되는지,
  오프라인 폰트·three.js가 로드되는지도 확인한다.
- M4: observe·capture·rescue와 발견 순간·수신 끊김 화면을 비교한다.
  phase·led·run.state의 기존 우선 규칙과 문구를 검증한다.
- M5: 시작 길게 누르기, 즉시 비상착륙, LANDING 잠금, 연결 끊김 배너,
  키보드 포커스와 명령 응답 상태가 명확하게 보이는지 확인한다.
- 이 참고 문서는 해당 화면의 구현이나 시각 검증 완료를 뜻하지 않는다.
  실행·mock·내러티브의 기존 질문은 2026-09-13 v2.3에서 별도로 결정됐다.
