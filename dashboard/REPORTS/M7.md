# M7 설치·실행 스크립트와 단계별 테스트 킷 — 2026-09-13

M7의 당시 결과를 보존한 보고서다. 최종 리뷰 D1–D5의 설치·기록기 후속 검증은
[M8 설치 manifest](evidence/M8_install_manifest.log)와 아래 정정한 증거를 기준으로 한다.

## 한 것

- `install.sh`: 일반 사용자 실행, 필요한 apt 패키지만 내부 sudo로 설치, 기존 인터페이스 import 확인, 누락 인터페이스만 빌드, 기존 `.colcon_install_layout`에 맞는 isolated/merged 플래그, aideck 패키지 항상 재빌드, 실제 설치 경로·선택된 Python 모듈의 소스 해시까지 자기검사. 기존 AI Deck ROS 패키지의 NumPy/OpenCV 실행 의존성도 설치하고, 노드의 실제 import·합성 ArUco 검출·JPEG 인코딩/디코딩을 검사한다.
- `run.sh`: 프로젝트 환경을 source하고 로그를 tee에 복제하며 Python 서버로 exec. 서버 PID와 SIGINT 처리를 직접 확인했다.
- `kiosk.sh`: 실제 실행에서 X11 연결 확인, 브라우저 탐색, HTTP 응답 대기, 서로 다른 admin/visitor 프로필, 설정의 visitor offset, 0.7–1.6 배율, `FX=low`. M8 후속 dry-run은 X 검사도 생략한다.
- `tests/stage_probe.py`: 관리자 WebSocket에 **읽기 전용**으로 연결한다. 단계·run·이벤트 변경 시각, 5초 간격 역할/전체 인벤토리 표, 실제 바이너리 카메라 수신 fps, 서버 pose 신선도, 전체 hello/state JSONL, pose CSV, 재접속을 지원한다. 명령을 보내는 코드가 없다.
- `tests/analyze_stage.py`: JSONL에서 중복 이벤트를 제거하고 phase/run/비상 착륙 이벤트 타임라인과 reset→READY 시간을 출력한다.
- `docs/stage_a.md` … `stage_d.md`: 단계별 기대값·명령·운영 기록란. 인계 계획의 `tests/stage_a_expectations.md`, `stage_b_expectations.md`, `stage_c_expectations.md`, `stage_d_checklist.md`는 해당 문서로 연결한다.
- `tests/test_stage_tools.py`: 기록 정확성, 이벤트 중복 방지, 읽기 전용 WS, 카메라 수신률, pose 신선도, 분석, Bash 문법, 배율/X11 입력, 전체 sudo 거부를 검사한다.

[README](../README.md)에 기존 클론 갱신·설치·설정·mock·실행·점검·복구의 7단계, 로스터 교체·이름 변경 절차를 작성했다. [FINAL](FINAL.md)에 M4–M7 결과·424/46개 회귀·Stage A 시작 절차·미완료 2건을 모았다.

영상 회귀용 OpenCV 4.10을 추가한 [Docker 검증 환경](evidence/M7_test_environment.log)과 기본 하네스에서 영상 실행 회귀가 SKIP되는 차이를 README에 명시했다. 운영 설치는 Ubuntu OpenCV 4.5.4 경로로 별도 검증했다.

설치 검증용 Chromium은 실제 Linux arm64 Chromium 140.0.7339.16 실행 파일이며 X 서버는 실제 Xvfb다. `xrandr`가 보고한 것은 **3840×2160 가상 모니터 1개**다. 행사장의 실제 듀얼 모니터 배치·GPU 가속·관람 가독성을 검증한 것으로 간주하지 않는다. Playwright/Xvfb는 이 폐기 가능한 개발 컨테이너 준비에만 쓰였으며 대시보드 런타임 의존성에 추가하지 않았다. [준비 스크립트](evidence/M7_prepare_container.sh)는 실제 저장소 패키지를 복사하며 가짜 ROS/브라우저 명령을 만들지 않는다.

## 스펙과 다르게 한 것

- §5.1 HTTP 대기는 curl 대신 Python 표준 라이브러리 urllib로 수행한다. 추가 런타임 패키지 없이 동일하게 HTTP 200을 기다린다.
- D4 리드 결정대로 실제 키오스크는 비-X11에서 경고 후 진행하지 않고 exit 2로 차단한다. README에 로그인 화면의 Ubuntu on Xorg 재로그인 절차를 추가했다. `--dry-run`은 DISPLAY·세션 종류·xrandr 검사를 생략하고 창/네트워크/프로필을 만들지 않는다.
- 기존 `setup_env.sh`의 `~/COSHOW` 전제는 수정하지 않는다. D5 설치기는 다른 클론 경로를 apt/setup 전에 명시적으로 차단하며 README에도 전제를 적었다. M8에서는 같은 `~/COSHOW` 경로를 별도 컨테이너마다 사용해 isolated overlay 혼입을 배제했다.
- 기존 overlay가 없는 깨끗한 소스 복사에서는 Humble underlay로 인터페이스를 먼저 만든 후 기존 프로젝트 `setup_env.sh`를 source한다. 기존 install이 있으면 먼저 프로젝트 환경을 source하고 import 여부를 검사한다.
- merged 설치의 정상 aideck prefix는 `install/aideck_aruco_ros`가 아니라 `install`이다. 실제 colcon 레이아웃을 읽어 이에 맞게 검사한다.
- 대시보드 Python 런타임은 aiohttp/PyYAML만 추가한다. NumPy/OpenCV는 이미 존재하던 `aideck_aruco_ros/package.xml` 실행 의존성이며, colcon build가 이를 설치하지 않으므로 설치기가 누락 apt 패키지를 준비한다. 노드 import 검사는 생성자를 호출하거나 UDP 소켓을 열지 않는다.
- Stage B의 “stage 4 무장 직전까지 수동 관찰”은 자동 전이와 경합하므로 운영 절차로 제시하지 않는다. 필수 Stage B는 프로펠러 분리 상태의 읽기 전용 수신/로스터 검증이며, 기존의 검증된 차단 조건이 있을 때만 단계 1–3을 선택적으로 관찰한다. 무장 확인은 Stage D에서 수행한다. 안전 시퀀스 자체는 변경하지 않았다.
- README 수동 복구 대기는 스펙 예문의 8.5초 대신 현재 BT YAML의 착륙 8초 + 2초 = 10초를 안내한다. 이미 전송된 SIGINT를 반복하지 않도록 신원/receipt 기반 재시작 복구를 우선하고 이전 종료 요청을 확인하도록 했다. 안전 시퀀스는 그대로다.
- 기본 관리자 UI는 역할 6개를 표시한다. `--fleet`의 전체 14행은 고급 진단용이며 기본 화면 구성과 분리한다.
