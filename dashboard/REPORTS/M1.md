## 스펙과 다르게 한 것 (있으면)

- §4.1 `search_progress`는 JSON 예시의 중첩 `{wp,total}` 대신 상세
  주의와 원본 코드가 지정하는 드론별 정수 인덱스를 사용했다.
- `_phase`는 누락·preflight 게이트 다음에 구조 완료→목표 발견→미션
  발견 순서로 진행 사실을 판정한다. §4.1 표에는 첫 행 우선 규칙이 없으며,
  복귀 중인 판독 드론의 위치 때문에 `return`이 `handover`로 되돌아가는
  모순을 피한다. 기존 완료·도착 수식은 바꾸지 않았다.
- preflight 상태의 초기값은 `stage=0`, 네 단계 모두 `pending`이다.
  실제 점검 메서드에 진입하면 1–4로 바뀐다.
- §4.3 하트비트 검사는 0.1초 타이머에서 수행하고, 마지막 발행 이후
  단조 시각 1초가 지나야 재발행한다. 1초 타이머와 1초 게이트를 겹치면
  스케줄링 오차로 출력이 2초 간격이 되는 문제를 회귀 테스트로 확인했다.
  기존 `/preflight/ready`의 1초 타이머는 유지했다.
- M1 pose 주입은 `verify_m1_ros.py`의 작은 ROS fixture로 수행했다.
  M2에서 `mock.scenario(t)`와 공유할 `fake_ros_world.py`는 아직 구현하지
  않았다. GUI 스크린샷은 M1 수용 조건이 아니며 M3부터 남긴다.

## M1 후속 수정 — 2026-09-13, M2 첫 커밋

사용자가 전달한 `reviews/M1_review_and_M2_directive.md` §2의 4건을
현재 코드에서 재현한 뒤 수정했다.

- `_DroneService.run`: `cmd.goal`을 `sig[2:]`로 기록한다. `DroneGoTo`와
  `DroneTakeoff`의 실제 발행 JSON에서 숫자만 남는지 검사한다.
- `Preflight._publish_status`: 단계·ready·abort와 드론 관문/무장 전이만
  즉시 발행한다. 배터리·pose_err·kal_range 연속값은 1 Hz 하트비트에서
  최신 스냅샷으로 보낸다.
- `Preflight._publish_ready`: ready 읽기부터 publish까지 같은 RLock을
  쥔다. 지연된 True 발행과 `_set_ready(False)`를 경쟁시킨 회귀에서
  마지막 발행이 False인지 확인했다.
- `UpdateBlackboard._publish_mission_state`: 표시용 직렬화·발행 전체를
  예외 격리한다. 경고는 한 번만 시도하며 경고 자체가 실패해도 BT tick을
  중단하지 않는다.

권고 사항도 반영했다. 런치 테스트는 `launch_ros.evaluate_parameters`의
최종 `bool`을 검사한다. 범위 검사는 실제로 동일성을 단언하는 함수 수와
변경 함수 목록을 출력한다. 근거 없는 독립 리뷰 무결함 문구는 제거했다.
