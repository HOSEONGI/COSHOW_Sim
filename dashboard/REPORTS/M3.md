6. `ros_io.py`: 타입 설정의 미지원 키·누락 키를 검증한다.

8. `server.py`, `state.py`, `checklist.py`: 송신 예외 시 경고·닫기·소켓 제거, 집계 예외 후 다음 tick 계속, ready 단독 latch 표시, 외부 preflight 수신 목록의 긴 쪽 선택을 구현했다.

권장 사항도 적용했다: 잠금 안의 `set_run/set_stack`, LIMO 배터리 임계값 주석,
M2 보고서 RED/GREEN 입력 계수 구분, 프로브의 스페어 blocking 실제 관측값.

### 대비 측정과 범위

최종 FHD search에서 실제 computed color가 `--ink-2`인 **36개 텍스트 요소**를
찾아 글자만 투명하게 하고, 배경·blur·saturation을 유지한 스크린샷의 각 요소
범위 모든 픽셀을 검사했다(단위·샘플 영상 배지 포함). `fg = .72×[244,246,251]
+ .28×bg`로 합성한 뒤 sRGB 선형화와 WCAG 상대휘도로 `(Lfg+.05)/(Lbg+.05)`를
계산했다. 측정 후 스타일은 제거했고 정상 글자가 있는 스크린샷을 증거로 저장했다.

| 실제 배치의 대표 라벨 | 배경 RGB | 최소 대비 |
|---|---|---:|
| 좌측 역할 패널 배터리·고도 | 35,45,83 | **7.182:1** |
| 미션 정보 패널 | 49,59,95 | **6.122:1** |
| 우하 warm 영향을 받는 구조 차량 임무 | 77,67,79 | **5.435:1** |

실제 배치의 36개 모두 4.5:1 이상이다. **광원 정점 위 어디에나 유리를 놓아도
4.5:1이라는 뜻은 아니다.** 이를 구분하기 위해 대시보드를 숨기고 동일 토큰의
임시 유리 패널을 양쪽 광원 모서리에 배치해 별도로 측정했다:

| 임시 배치 | glass .10 | glass-strong .16 |
|---|---:|---:|
| cool 좌상 모서리 | **3.562:1** | **3.212:1** |
| warm 우하 모서리 | **4.802:1** | **4.151:1** |

[광원 위치 보조 측정](evidence/M3_contrast_peaks.log). 따라서 원래 토큰과
“두 광원 정점 위에서도 4.5:1”을 동시에 만족했다는 수용 주장은 하지 않는다.

## 스펙과 다르게 한 것 (있으면)

- §5.7 ROS 경계의 노드 정보는 기존 `(name, namespace)` 튜플을 유지하고 체크리스트에서 full-name을 계산한다. 이미 검증한 외부 노드 개수 판정의 입력 형태를 유지했으며, 이 계산에는 ROS 타입이나 새 구독이 필요하지 않다.
- M3 지시 §3.1/§3.4: 색상·유리 토큰을 유지하고 **라벨을 광원 정점에서 벗어나게 배치해 실제 화면 대비를 충족**했다. 정점의 임의 유리 배치까지 요구하면 위 측정처럼 토큰과 모순된다. 사용자의 “안전/보호 범위 외에는 먼저 구현하고 이유 보고” 지시에 따라 이 해석을 적용했다. M4에서 배경 장면이나 라벨 위치가 바뀌면 다시 측정해야 한다.
- M3 지시 §3.1/§3.5: FHD 토큰 상한 56/30/15/22px를 그대로 두되 2560px 이상 화면에서 상한을 최대 2배로 확장했다. 간격도 FHD 8px 단위를 4K 16px 단위로 확장했다. 헤더는 명시된 64px 상한을 유지하므로 세로 비율은 완전히 2배가 아니다.
- M3 지시 §3.2: 2줄 고정 내러티브와 대기 3문장 규칙이 충돌한다. 실행 중 바는 정확한 2줄 높이, 대기 때는 같은 캔버스 위에 3문장용 별도 유리 영역을 겹친다. 바깥 그리드와 캔버스 크기는 바뀌지 않는다.
- M3 지시 §3.2: 필드는 대략 5:4 대신 `hello.field`의 실제 arena+LIMO 영역 합집합인 **7:6**을 사용했다. 좌표 사본은 없다. 원시 이름은 최신 지시대로 역할 패널의 작은 보조 표기에만 사용한다.
- 원본 파일의 동일성을 보존하기 위해 Pretendard 라이선스와 three.core.js의 기존 공백 2건도 유지했다. 전체 `git diff --check`에는 이 원본 공백 경고가 있으며 자체 작성 파일 검사는 통과한다. [출력](evidence/M3_diff_check.log).
