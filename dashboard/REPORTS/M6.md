# M6 로스터·플릿·스택 — 2026-09-13

## 한 것

- `fleet.py`: 10대 드론/4대 LIMO 인벤토리의 역할 배정, 최초 enabled URI 기반 로스터, 검증·추천·atomic 저장, 생성 파일 3종과 결합 SHA-256을 구현했다. 협업자 템플릿은 읽기만 한다.
- `crazyflies.generated.yaml`은 템플릿의 robots만 교체한다. 역할은 BT base, 스페어는 field의 격자 위치, 전체 enabled/cf21과 라디오당 5대 이하를 검사한다. 카메라 생성 설정과 제어 대상은 역할 드론뿐이다. 물리 기체 IP를 사용해 교체 기체에 기존 역할 IP를 잘못 붙이지 않는다.
- IDLE에서만 스택 기동·재기동·로스터 변경을 허용한다. 소유한 자식은 새 세션/env/core0으로 실행하고 SIGINT 후 최대 10초, 필요 시 프로세스 그룹 SIGKILL로 정리한다. 외부 graph 스택을 종료하지 않는다.
- 생성/적용 해시를 구분한다. 로스터 저장 후 재기동 전에는 시작 게이트를 막고, 소유 프로세스가 죽으면 적용 해시를 무효화한다. `state.py`는 소유 노드를 external로 덮어쓰지 않으며 중복 노드를 구별한다.
- `server.py`: 로스터 저장 시 구독·ping을 재설정하고 이전 기체 receipt/JPEG를 비운 후 WS를 재접속시킨다. hello schema와 4개 WS 명령은 그대로다. 관리 부가 동작은 loopback HTTP API다.
- `config.py`: mock 로스터는 `run/mock`에 분리한다. 잘못된 경로·쓰기 실패·설정 생성 실패에도 HTTP/WS 관측은 유지하고 오류를 표시한다.
- `fleet-ui.js`: 기본 화면은 역할 6대, 전체 14행은 접힌 교체 설정에 있다. 추천은 저장하지 않고 이전→이후 확인창 뒤 저장한다. 재접속 때 설정을 다시 받아 오래된 draft/확인창/추천 응답을 폐기한다. 저장은 검토한 expected_hash를 함께 보내 동시 수정 덮어쓰기를 방지한다.

## 스펙과 다르게 한 것

- **사용자 최신 지시를 우선해** §5.8의 상시 14행을 기본 6행 + 접힌 교체 인벤토리로 바꿨다. 참관자에는 여유 기체를 렌더링하지 않는다. 백엔드 전체 관측·스페어 무장 경고·라디오 검사는 유지한다.
- 로스터·스택 관리는 `/api/fleet`를 사용해 계약의 WS 명령 4개를 늘리지 않는다. `/api/admin`에 관리 메타데이터와 생성 해시를 제공한다.
- mock도 로스터 변경을 재현하되 별도 경로에 저장하고 실제 subprocess를 실행하지 않는다.
- HTTP 저장에 선택적인 expected_hash를 추가해 다른 관리자에서 바뀐 설정을 옛 확인창으로 덮지 않게 했다.

## 열린 질문 / 사용자 결정 필요

- **스택 고아 프로세스 정책 답변 대기.** §5.5의 고아 PID 정리 범위에 독립 수명의 스택까지 포함할지 모호해 질문했다. 현재 BT/preflight는 신원·SIGINT 기록으로 복구하며, 이전 서버가 남긴 스택은 새 서버의 소유 자식으로 채택하거나 임의 종료하지 않는다. graph에 보이면 외부 스택으로 표시·차단한다. 스택 고아 PID만 남아 graph가 아직 보이지 않는 재기동 경계의 통합 복구는 미완료다. 전체 비상 시퀀스를 임의 변경하지 않았다.
- 추가 기체 6대의 실제 URI/IP와 LIMO 상태 타입은 운영자가 확인해야 한다. null을 실제 주소로 추정하지 않았다.
