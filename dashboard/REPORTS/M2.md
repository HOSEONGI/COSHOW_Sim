## 한 것

  [문서 SHA256](evidence/M2_sources.log). 작업 브랜치는 `dashboard`다.

  플릿·로스터를 읽고 BT 설정에서 hello의 베이스·레인·관측점을 계산한다.
  설정 누락은 해당 체크리스트 행과 전역 오류에 표시한다.
- `ros_io.py`: 동적 타입을 사용한 유일한 ROS 어댑터. 역할과 스페어 Status,
  LIMO 4대 odom을 관측하며 카메라·제어 클라이언트는 역할 기체에만 만든다.
  타입 누락·잘못된 JSON·NaN은 해당 채널에서 격리한다.
- `state.py`: ROS 콜백 스레드에서 즉시 `time.monotonic()` 수신 시각과 최신
  데이터를 기록한다. 잠금으로 일관된 스냅샷을 만들고 detection hold,
  LED·cmd 파생, 프레임 최신 슬롯, 이벤트 200건/최근 30건을 관리한다.
- `server.py`: hello 1회, state 10 Hz, `[index][JPEG]` 전달과 정적 파일 제공.
  소켓마다 상태 1개·카메라별 최신 프레임·송신 태스크를 두며 각 send는
  5초 제한이다. 관리자는 로컬 주소만 허용하고 visitor 명령은 거부한다.
- `checklist.py`: §5.5 전체 표의 순수 판정, blocking/non-blocking/skipped/
  정보 없음 구분, 외부 노드 개수·20초 잔류·최근 실수신 판정.
- `pinger.py`: 전체 플릿 시스템 ping, 셸 없이 실행, 시간 초과·취소 시 회수.
- `mock.py`, `static/mock/camera.jpg`: 공유 시나리오, 6개 스페어 중 하나의
  링크 장애, 점검 성공/실패. handover 동안 탐색기는 지상 대기하고
  target_confirmed부터 red, 구조 도착부터 green으로 바뀐다.
- `tests/`: 코어·체크리스트·ROS 어댑터 테스트와 공유 시나리오 ROS fixture,
  두 소켓 프로브, 정상/오타 그래프 CLI 검증. `README.md`에 현재 실행법을 적었다.
- `Design.md`: Apple 참고를 유지하면서 카메라/패널 수를 v2.3의 설정 파생
  규칙으로 갱신했다. UI 구현 완료를 뜻하지 않는다.

## 스펙과 다르게 한 것 (있으면)

- §5.3 예제에는 타입 필드 위치가 없다. 기존 이름/템플릿 키를 유지하고
  §5.7 타입 요구를 `types.{topics,services,actions}` 매핑으로 추가했다.
- §5.4 체크리스트 기본 6필드에 `status`를 추가해 skipped·정보 없음·경고를
  구분한다. LIMO 팩 임계값은 미정이므로 드론 전압 임계값을 임의로 적용하지
  않는다. optional `limo_battery_v`가 없으면 전압 표시만 한다(non-blocking).
- §5.6 정적 mock JPEG는 기체별 같은 사본 대신 `static/mock/camera.jpg`
  하나를 재사용한다. 바이너리 인덱스와 카메라별 최신 슬롯은 분리돼 있다.
- mock은 메모리에서만 4역할 로스터·3라디오·누락 IP·BT 플래그를 fixture로
  채운다. 실제 파일의 미설정 값과 불안전 플래그를 검증한 결과로 간주하지 않는다.
- 실제 모드의 실행 제어는 리뷰 §5가 정한 M5 범위이므로 모든 명령을 명시적으로
  거부한다. mock의 가상 전이는 UI 개발용이며 실제 estop 순서를 증명하지 않는다.
- M2 로스터는 읽기/초기 관측 배정만 제공한다. 저장·생성 파일·applied_hash 기록·
  스택 기동은 M6, 고아 pid 탐지·소유 프로세스 감시는 M5에서 연결한다.
  해당 체크리스트 판정은 주입된 context로 검증했다.
