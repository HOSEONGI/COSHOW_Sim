## 한 것

### M3 후속 수정

첫 커밋 `efce545`으로 필수 4건과 회귀·증거를 분리해 푸시했다.

1. `hello`에 BT에서 읽은 `observe_drone`, `mission_marker_ids`, `marker_id_offset`을 추가했다. 프론트의 판독 드론 추론과 고정 마커 범위를 제거했다. BT 값이 없으면 null이며 프론트가 임의 범위를 만들지 않는다.
2. 외부 이름 감사가 `static/**/*.js`의 문자열·숫자 리터럴을 검사한다. 주석과 동봉 vendor는 제외하고 파일·리터럴 수를 출력한다. 이스케이프 문자열·템플릿 내부 표현식과 숫자 범위 회귀를 포함했다.
3. 연결 대기를 내러티브 바 위 우측으로 이동했다.
4. 헤더를 `min-height`, 단계 알약 패딩을 고정 8px/16px로 바꾸고 헤더 자손 경계를 검사한다. 4K 헤더는 **71px**이며 자식이 모두 포함된다. 이전 64px 고정에서는 run-summary가 위·아래로 약 5px씩 넘쳤다.

### 본 구현

- `twin.js`, `twin-model.js`: arena와 LIMO 구역을 하나의 불투명 남색 입체 무대로 구성했다. 0.5m 격자·목표 타일·관측 링·동적 레인·드론 십자와 링·고도 스템·LIMO 방향 쐐기·cool/warm 조명을 만들었다. 마우스 조작·그림자맵은 없고 화면 비율에 맞춰 자동 프레이밍한다.
- **사용자 최신 요청대로 역할 드론 4대와 LIMO 2대만 렌더링한다.** 여유 드론·LIMO와 spare_area는 무대에서 제거했다. LIMO 구역을 따로 떠 있는 조각으로 분리하지 않고 같은 바닥에 연결했다. 표시 이름의 화면 투영 경계를 계산해 겹치면 라벨만 옮기며 기체 좌표는 유지한다.
- 드론 궤적은 각 128개 고정 링버퍼의 10초 페이드다. 발견 링·복귀 wash를 재사용하고, IDLE에서만 공전한다. 신선도/연결/착륙 우선순위, reduced-motion, 최대 60fps, pixelRatio≤1.5/low=.75, contextlost 재로드를 적용했다.
- `camera.js`, `visitor.js`, `ws.js`: `[idx][JPEG]`를 Blob→ImageBitmap→canvas로 그린 뒤 close한다. 디코딩 중인 타일은 새 프레임을 버린다. 최초 비트맵 크기로 해상도를 맞추고 대기/끊김 오버레이를 구별한다. 카메라는 팝업 없이 타일 4개에 임베드된다.
- `visitor.html`, `glass.css`: 카메라 영문 fixture 문구를 제거하고 이름/관심 id/MOCK 배지만 남겼다. 미션 판독과 조난자 발견을 구별하고 P_N 발견 후 값도 검증했다. 내러티브 텍스트만 200ms 교차 페이드하고 DONE을 유지한다.
- `nodes/aruco_detector_node.py`: 허용된 §4.6의 JPEG q80/BGR annotation/fps/3초 stream heartbeat를 display와 독립적으로 추가했다. 기존 UDP 수신·검출 결과는 변경하지 않았다. AST 감사가 추가분을 제거해 기존 전체 AST와 비교한다.
- mock JPEG는 기존 장면의 텍스트를 imagegen으로 제거한 결과다. 생성 도구 출력 원본은 로컬 generated_images에 보존했고 최종 JPEG 324×244를 저장소에 동봉했다. 런타임 생성·다운로드는 없다.

## 스펙과 다르게 한 것 (있으면)

- 사용자 최신 지시가 §6.2/M4의 여유 기체 표시보다 우선한다. 역할 6대만 표시하고 spare_area를 프레이밍 범위에서 뺐다. 백엔드 인벤토리와 안전 점검은 그대로 유지한다.
- 렌더 작업을 최대 60fps로 제한해 고주사율 화면에서도 불필요한 GPU 작업을 줄였다.
- 후속 수정은 최신 리뷰 지시 그대로다. 4K 헤더 64px 상한은 v2.5 리뷰의 `min-height` 지시로 대체됐다.
